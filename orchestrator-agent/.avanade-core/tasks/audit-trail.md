# Audit Trail Task

**Task ID:** audit-trail  
**Agent:** Orchestrator  
**Version:** 1.0

---

## Purpose

Maintain a comprehensive audit trail of all project activities, gate validations, agent transitions, and artifact changes for compliance and traceability.

---

## Audit Trail Structure

### Location

```
{workspace}/
└── .orchestrator/
    └── audit/
        ├── audit-trail.md          # Main audit log
        ├── gate-history.md         # Gate validation history
        └── sessions/
            └── session-{date}.md   # Daily session logs
```

---

## Audit Entry Format

Each entry in the audit trail follows this structure:

```yaml
- timestamp: "YYYY-MM-DD HH:MM:SS"
  action: "{action_type}"
  agent: "{agent_name}"
  user: "{user_identifier}"
  details:
    description: "{what_happened}"
    artifacts: ["{affected_artifacts}"]
    result: "{success|failure|partial}"
  context:
    phase: "{UPSTREAM|MIDSTREAM|DOWNSTREAM}"
    gate: "{gate_id if applicable}"
```

---

## Action Types

| Action Type | Description | Trigger |
|-------------|-------------|---------|
| `GATE_VALIDATION` | Gate validation attempt | *gate-1, *gate-2, *gate-3 |
| `GATE_PASS` | Gate passed successfully | Gate validation success |
| `GATE_FAIL` | Gate validation failed | Gate validation failure |
| `AGENT_ROUTE` | Routing to different agent | *route command |
| `ARTIFACT_CREATE` | New artifact created | Agent creates file |
| `ARTIFACT_UPDATE` | Existing artifact modified | Agent modifies file |
| `ARTIFACT_DELETE` | Artifact removed | Agent removes file |
| `PHASE_CHANGE` | Project phase transition | Gate passage |
| `SESSION_START` | Work session started | Agent activated |
| `SESSION_END` | Work session ended | Agent deactivated |

---

## Execution Steps

### Step 1: Initialize Audit Structure

If audit folder doesn't exist, create it:

```
mkdir -p {workspace}/.orchestrator/audit/sessions
```

### Step 2: Check Existing Trail

Load existing audit-trail.md if present.

### Step 3: Record New Entry

Append new entry with timestamp and details.

### Step 4: Update Gate History

If gate-related action, also update gate-history.md.

### Step 5: Generate Summary

On request, generate audit summary report.

## Commands

| Command | Description |
|---------|-------------|
| `*audit` | Show recent audit entries |
| `*audit full` | Show complete audit trail |
| `*audit gates` | Show gate history |
| `*audit summary` | Generate audit summary report |
| `*audit export` | Export audit to specified format |

---

## Retention Policy

- **Active Project:** Keep all entries
- **Completed Project:** Archive after 90 days
- **Session Logs:** Keep for 30 days, then consolidate

---

## Integration

The audit trail integrates with:
- Gate validation tasks (auto-log gate attempts)
- Routing task (auto-log agent transitions)
- All artifact creation/modification tasks
