**Data:** 2026-06-18  
**Status:** 🟡 Design | Implementation TBD  
**Audience:** Architects, Agents, AI Leadership

---

## Executive Summary

The **AI Engineer Coach** (an agentic-engineering analyzer) can be integrated into the Data Migration Factory as a **continuous best-practices mentor**. It will analyze agent execution patterns across waves, detect 6+ critical anti-patterns specific to data migrations, and auto-recommend skill reuse and agent improvements.

**Expected ROI:**
- 🟢 30% reduction in GateScore variance (more predictable quality)
- 🟢 Detect silent failures (executor not writing files) before Gate 3
- 🟢 Identify and package 5–10 reusable skills per factory (code reuse +40%)
- 🟢 Reduce agent context bloat (artifacts stay < 40k tokens)

## Part 2: The 6 Critical Anti-Patterns for DMF

### 1️⃣ Wave Completion Anti-Pattern
**Problem:** Entities discovered by `discovery-scout` are not referenced in downstream agents' outputs.

**Detection:**
```yaml
rule: wave-completion
trigger:
  - Gate 1 artifact references 127 entities
  - Gate 2 STTM only maps 98 entities
  - Gap: 29 orphaned entities (23%)
severity: HIGH
action: "Re-run business-analyst with explicit entity-list input"
metric: entity_coverage_ratio
```

**Score Impact:** `-15 points` on Gate 2 → GateScore from 0.82 → 0.75

---

### 2️⃣ STTM Stability Anti-Pattern
**Problem:** Business-analyst regenerated STTM multiple times, signaling unclear requirements or bad input.

**Detection:**
```yaml
rule: sttm-stability
trigger:
  - Business-analyst artifact v1 at 14:00
  - Business-analyst artifact v2 at 14:35 (35 min delta, 67% line change)
  - Business-analyst artifact v3 at 15:10
condition: "3+ regenerations in < 2 hours"
severity: MEDIUM
action: "Suggest requête with stakeholders before Gate 2 sign-off"
metric: artifact_regeneration_count
```

**Why it matters:** Instability in STTM cascades to Data Modeler (v1, v2, v3) → scope creep → missed Gate deadline.

---

### 3️⃣ Model Overreliance Anti-Pattern
**Problem:** Expensive models (GPT-4, Claude Opus) used for simple, deterministic tasks (inventory, parameter extraction).

**Detection:**
```yaml
rule: model-overreliance
trigger:
  - discovery-scout used GPT-4 (5 calls × $0.015/call = $0.075/wave)
  - inventory-scout used GPT-4 (8 calls)
  - logic-extractor used Opus (3 calls)
total_wave_cost: "$18.50"
potential_savings: "Use Claude Haiku for parametric tasks → $2.10 (88% savings)"
severity: LOW
action: "Downgrade discovery-scout, inventory-scout to Haiku in wave config"
metric: cost_per_token
```

---

### 4️⃣ Context Bloat Anti-Pattern
**Problem:** Artifacts grow too large, consuming context window inefficiently; auto-compaction kicks in repeatedly.

**Detection:**
```yaml
rule: context-bloat
trigger:
  - Gate 1 discovery artifact: 22,500 tokens
  - Gate 1 STTM artifact: 18,300 tokens
  - Gate 1 DQ rules artifact: 12,400 tokens
total: "53,200 tokens (77% of 69k context window)"
severity: MEDIUM
action: "Split inventories into Wave A (core entities) and Wave B (audit columns)"
metric: artifact_size_bytes
```

---

### 5️⃣ Silent Executor Failure
**Problem:** Downstream-executor says "success" but actually wrote 0 rows or skipped execution.

**Detection:**
```yaml
rule: silent-executor-failure
trigger:
  - Downstream-executor output: 847 tokens (< 1000 threshold for "real work")
  - Output contains placeholder text: "Ready to apply..."
  - Actual DDL file size: 2.1 KB (suspicious — should be > 10 KB for typical table)
condition: "output_tokens < 1000 AND no_actual_artifacts"
severity: CRITICAL
action: "Auto-trigger self-healing agent"
metric: executor_output_fidelity
```

---

### 6️⃣ Gate Score Regression
**Problem:** Quality metric drops wave-over-wave, indicating systemic issues (fatigue, scope creep, bad discovery input).

**Detection:**
```yaml
rule: gate-score-regression
trigger:
  - Financeiro Wave 1: GateScore 0.89 🟢
  - Financeiro Wave 2: GateScore 0.81 🟡 (7-point drop)
  - Financeiro Wave 3: GateScore 0.76 🔴 (5-point drop)
  - Trend: -7%, -5% (accelerating)
severity: HIGH
action: "Trigger iteration-improvement agent. Likely causes: (a) discovery rush, (b) STTM instability, (c) context bloat"
metric: gatescore_trend
```

### Current Flow

```

  Entity count        STTM check          Executor
  STTM ready?         Model cost          verification
```

### Implementation Points (3 hooks)

#### Hook 1: After Agent Execution (ANY agent)
**Location:** `migration-coordinator.py` → `def spawn_agent(agent_id, ...)`

```python
def spawn_agent(agent_id: str, wave: str, gate: int, ...):
    result = agent_execution(...)
    
    # NEW: Telemetry collection
    telemetry_collector.log_execution(
        agent_id=agent_id,
        wave=wave,
        gate=gate,
        model=result.model_used,
        tokens_in=result.tokens_input,
        tokens_out=result.tokens_output,
        artifact=result.artifact,
        artifact_size=len(result.artifact),
        execution_time_sec=result.duration,
        timestamp=datetime.now()
    )
    
    return result
```

**File to create:** `src/shared/coaches/telemetry_collector.py`

---

#### Hook 2: Before Gate Sign-Off (quality-gate.py)
**Location:** `quality-gate.py` → `def calculate_gatescore(...)`

```python
def calculate_gatescore(artifacts: dict, wave: str, gate: int):
    # Existing score calculation
    base_score = existing_gatescore_calc(...)
    
    # NEW: Anti-pattern detection
    anti_patterns = anti_pattern_detector.detect(artifacts, wave, gate)
    
    # Adjust score based on detected issues
    adjustment = sum([ap.score_impact for ap in anti_patterns])
    final_score = base_score + adjustment
    
    # Log findings
    logger.info(f"Wave {wave} Gate {gate}:")
    for ap in anti_patterns:
        logger.warning(f"  - {ap.name}: {ap.action}")
    
    return final_score, anti_patterns
```

**File to create:** `src/shared/coaches/anti_pattern_detector.py`

## Appendix A: Full Anti-Pattern Rule (Example #1)

**File:** `.coach/rules/wave-completion.yaml`

```yaml
---
name: "Wave Completion Anti-Pattern"
category: "business-logic"
severity: "high"
description: |
  Detects when discovered entities are not fully represented in
  downstream Gate artifacts (STTM, data model, DDL).

trigger:
  gate_1_entities: "{{ discovery.entity_count }}"
  gate_2_sttm_mapped: "{{ sttm.mapped_entity_count }}"
  gap_threshold_pct: 10  # Flag if gap > 10%

detection_logic:
  - name: "entity_coverage"
    operator: "less_than"
    lhs: "{{ gate_2_sttm_mapped }}"
    rhs: "{{ gate_1_entities * 0.90 }}"  # 90% coverage minimum
    flag_if: true
    
score_impact: -15  # Deduct 15 points from GateScore

action: |
  The following {{gap_count}} entities were discovered but not fully
  addressed in Gate 2 STTM:
  
  {{missing_entities}}
  
  Recommended action:
  1. Review STTM with business-analyst
  2. Confirm whether entities are out-of-scope or oversight
  3. If oversight, regenerate STTM
  4. Update Gate 2 decision log with rationale

examples:
  - wave: "Financeiro_wave_1"
    gate_1_entities: 127
    gate_2_sttm_mapped: 98
    gap: 29 (23%)
    action_taken: "Regenerated STTM, coverage → 125/127"
    outcome: "GateScore adjusted from 0.80 → 0.87"
```
